\section*{Introduction}

The previous chapters defined what the system must do and how it must be structured. This chapter focuses on the concrete realization of the web side of ForsaDrive. It describes the development environment, the technologies that were selected to build the application, and presents the main interfaces delivered at the end of the implementation phase.

Several tools supported the different phases of the project, from version control to testing and deployment. The main ones are listed below.

\section{Technologies Used}

The technological choices were driven by the constraints of the project, the experience already acquired during the training at ISET, and the standards adopted by the host organization.

\subsection{Frontend Technologies}

\subsubsection{PHP with HTML and Bootstrap}

The web interface is built with PHP rendered server-side, combined with HTML5 and Bootstrap 5 for layout and styling. PHP handles routing, session management, and page rendering in a unified server-side model, which avoids the complexity of a separate frontend build step. Bootstrap was chosen for its responsive grid system and its comprehensive set of UI components, which allowed the interface to be built consistently and quickly.

\subsubsection{Vanilla JavaScript}

Client-side interactivity is handled with plain JavaScript, without any additional framework. Dynamic behaviors such as form validation, tab switching in the administration panel, and AJAX calls for real-time feedback are implemented in small, focused scripts.

\subsection{Backend Technologies}

\subsubsection{PHP}

The backend business logic is written in PHP and exposed as a REST API under the \texttt{/api/} route prefix. PHP was selected because the host organization already operates a PHP-based infrastructure, the language is natively supported by XAMPP without any additional runtime, and the team had prior experience with it. The API follows a front-controller pattern: a single \texttt{index.php} entry point parses the URL, dispatches the request to the appropriate handler file, and returns a JSON response.

\subsubsection{Bearer Token Authentication}

Authentication relies on randomly generated bearer tokens stored in an \texttt{api\_tokens} table. After a successful login, the server creates a 32-byte hex token with a 30-day expiry and returns it to the client. Every protected endpoint validates the token from the \texttt{Authorization} header and rejects requests that carry an expired or unknown token.

\subsection{Database}

SQLite was selected as the persistent store. It is a file-based, serverless relational database that requires no separate process, which makes it easy to set up, back up, and share between the web and mobile clients through the same shared file. The database runs in WAL (Write-Ahead Logging) mode to support concurrent reads from the mobile application while the web server writes. Indexes are placed on the columns most frequently used for filtering, in particular the origin, the destination, and the departure date of rides.

\subsection{Other Tools and Services}

\begin{description}[noitemsep]
    \item[password\_hash / PASSWORD\_BCRYPT] Used for secure password hashing in PHP.
    \item[Firebase Cloud Messaging (via PHP)] Server-side FCM calls to deliver push notifications to mobile devices.
    \item[OpenStreetMap / Nominatim] Used for city geocoding lookups in the map feature.
    \item[PDO (PHP Data Objects)] Used for all database interactions to ensure safe, parameterized queries.
\end{description}

\section*{Conclusion}

This chapter described the realization of the web platform of ForsaDrive, from the development environment and the technological stack to the main delivered interfaces. The PHP and SQLite combination allowed the business logic and the database to be shared directly with the mobile application without any duplication. The resulting web application covers the primary workflows needed by passengers, drivers, and administrators. The following chapter focuses on the mobile counterpart, which shares the same backend and completes the user experience on the go.
